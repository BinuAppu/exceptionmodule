Exception Manager — Portable Local Docker Installation
=======================================================

This installation is intended for local evaluation, development, and internal
demonstrations. It is not a production deployment.


1. Prerequisites
----------------

Supported host options:

- Linux with Docker Engine and Docker Compose, or
- macOS/Windows with Docker Desktop (Windows commands should be run in WSL), or
- another host that can run Linux containers.

Required:

- Docker Engine or Docker Desktop
- Docker Compose v2 plugin (the legacy docker-compose command is also detected)
- Bash
- OpenSSL command-line tools
- curl
- Internet access during the first installation
- Enough memory for ClamAV; 4 GB RAM is recommended
- TCP port 8000 available, or another port configured through APP_PORT

Verify Docker is running:

    docker --version
    docker compose version

On hosts that only provide the legacy command, use:

    docker-compose version


2. Extract and install
----------------------

Open a terminal and change to the extracted project directory. Use the actual
path on the new host rather than reusing a path from another machine:

    cd /path/to/exception

For a new machine, copy the source tree but not .env,
initial-recovery-codes.txt, or Docker volumes. The installer should generate
new local secrets for that host.

Make the installer executable if necessary:

    chmod +x install.sh

Run the installer:

    ./install.sh

The installer:

- verifies Docker, Docker Compose, OpenSSL, curl, and Docker daemon access;
- creates .env from .env.example only when .env does not already exist;
- generates a unique PostgreSQL password, encryption keys, and temporary
  break-glass password;
- never overwrites an existing .env;
- pulls PostgreSQL and ClamAV;
- builds the FastAPI backend and React frontend into one non-root container
  image;
- starts PostgreSQL, ClamAV, the API, and the background worker;
- waits for /ready before reporting success; and
- saves first-login recovery codes to initial-recovery-codes.txt with mode 600.

An existing .env is preserved on later runs. This makes rerunning the installer
safe, but it also means an incomplete old .env must be repaired manually.

The first ClamAV start can take several minutes while signatures download and
initialize. The installer waits for up to 15 minutes.


3. Verify the installation
--------------------------

The following examples assume Docker Compose v2. Replace docker compose with
docker-compose if that is the only command installed on the host.

    docker compose ps
    docker compose logs --tail=100 api worker postgres clamav

Expected service behavior:

- api: healthy and publishing the configured APP_PORT
- worker: running without an inherited HTTP health check
- postgres: healthy
- clamav: healthy

Test the application:

    curl -fsS http://localhost:8000/health
    curl -fsS http://localhost:8000/ready

Expected health response:

    {"status":"ok"}

Expected readiness response:

    {"status":"ready","checks":{"database":"ok","storage":"ok"}}

Open the web application:

    http://localhost:8000

If APP_PORT was changed, replace 8000 in these URLs with that value.


4. First login and credential cleanup
-------------------------------------

On the login page:

1. Select "Break-glass access".
2. Enter BREAK_GLASS_USERNAME from .env. The default is breakglass-admin.
3. Enter the temporary password generated by install.sh.
4. Change the password immediately when prompted.

The installer prints the temporary password only after a successful install.
It is also stored as BREAK_GLASS_INITIAL_PASSWORD in .env so it is not lost.

The seed prints ten recovery codes once. On a fresh database they are saved in:

    initial-recovery-codes.txt

Move those codes to an approved offline password vault and then delete the
local file. The file is excluded by .gitignore.

After changing the first-login password, remove the initial password from .env.
This command works with both GNU sed and BSD sed:

    sed -i.bak 's/^BREAK_GLASS_INITIAL_PASSWORD=.*/BREAK_GLASS_INITIAL_PASSWORD=/' .env
    rm -f .env.bak
    chmod 600 .env
    docker compose up -d --force-recreate api worker

Removing the environment variable does not change the already-hashed password
stored in PostgreSQL.


5. Access from another computer
--------------------------------

The safe default binds only to 127.0.0.1. To access the application from
another computer on a trusted private network, edit .env and set the server's
actual reachable address in both settings:

    APP_BIND_ADDRESS=0.0.0.0
    ALLOWED_HOSTS=localhost,127.0.0.1,<server-lan-ip-or-dns-name>
    CORS_ORIGINS=http://<server-lan-ip-or-dns-name>:<APP_PORT>

Then recreate the application services:

    docker compose up -d --force-recreate api worker

Allow only the required port through the host firewall, then open:

    http://<server-lan-ip-or-dns-name>:<APP_PORT>

Do not expose this local evaluation setup directly to the public internet. Use
SSH port forwarding when direct network access is not required:

    ssh -L 8000:127.0.0.1:8000 <user>@<server>

Then open http://localhost:8000 on the client computer.


6. Manual .env setup (only if install.sh cannot run)
----------------------------------------------------

Copy the template:

    cp .env.example .env
    chmod 600 .env

Generate values:

    openssl rand -hex 24
    openssl rand -base64 32
    openssl rand -base64 32
    openssl rand -hex 14

Set the generated values in .env as follows:

    POSTGRES_PASSWORD=<first value>
    DATABASE_URL=postgresql+psycopg://exception_manager:<first value>@postgres:5432/exception_manager
    APP_ENCRYPTION_KEY=<second value>
    BACKUP_ENCRYPTION_KEY=<third value>
    BREAK_GLASS_INITIAL_PASSWORD=Em!<fourth value>

The Em! prefix ensures the temporary password has the required uppercase,
lowercase, and character-class variety. The hexadecimal PostgreSQL password
avoids URL-encoding problems. Do not use
"change-me", reuse the sample values, or commit .env to source control.

Validate and start:

    docker compose config
    docker compose pull postgres clamav
    docker compose build api
    docker compose up -d
    docker compose ps

Retrieve first-login recovery codes after the API is healthy:

    docker compose logs api | grep -A 11 "Break-glass recovery codes"


7. Common operations
--------------------

View logs:

    docker compose logs -f api worker

Restart services:

    docker compose restart api worker

Rebuild after source changes:

    docker compose build api
    docker compose up -d

Stop while preserving named database, ClamAV, and application volumes:

    docker compose down

Permanently delete all local application data:

    docker compose down -v

WARNING: "down -v" destroys the PostgreSQL, ClamAV, attachment, and backup
volumes. Back up required data before using it.


8. Troubleshooting
-------------------

Installer reports that the Docker daemon is unavailable

Start Docker Engine/Docker Desktop. On Linux, verify that the current user can
run:

    docker info

Port 8000 is already allocated

Set a different local port in .env:

    APP_PORT=8080

Then rerun:

    ./install.sh

The application remains available at http://localhost:8080.

ClamAV remains in the starting state

The first malware-definition update can take several minutes. View progress:

    docker compose logs -f clamav

The API is restarting

Inspect the effective configuration and recent logs:

    docker compose config
    docker compose logs --tail=200 api postgres clamav

The browser shows JSON instead of the login page

Run:

    ./install.sh

Then hard-refresh the browser with Ctrl+Shift+R and open:

    http://localhost:8000/login

Remote access returns a trusted-host error

Add the exact hostname or IP address used in the browser to ALLOWED_HOSTS in
.env, then recreate the api and worker services.

Password was lost before the first login

Use one of the saved recovery codes through the /api/auth/recovery endpoint
from approved administrative tooling. Do not place recovery codes or new
passwords in shell history or source control. If both the password and recovery
codes are lost, restoring a database backup or deliberately recreating the
local volumes is required; both options have operational consequences.


9. Production warning
----------------------

This Compose topology is for local/internal evaluation only. It does not by
itself provide TLS, a trusted reverse proxy, hardened secrets management,
private managed data services, high availability, tested backups, or complete
production monitoring.
